Clairemind — personal AI assistant on WhatsApp

Manages calendar, tasks, lists and reminders, understands voice messages and negotiates meetings with other people, all in natural language. Used daily in real life.

In progress
  • ~41% LLM cost saved with prompt caching
  • 5/5 adversarial privacy and jailbreak tests passed
  • Daily backups with validated restores

Problem

LLM assistants tend to claim actions they never performed and to invent missing data — names, phone numbers, times. For a secretary that edits your calendar and writes to other people, that is unacceptable.

Engineering decisions

  • Harness over prompt: the model decides what to do; the code controls how it comes out. Confirmations and agenda dates are generated by code, so the assistant never states an action it didn't execute or a date it made up.
  • Structural fixes beat prompt fixes: required schema fields pushed the model to guess missing data. Making them optional and letting the code pick the default fixed it; "don't invent" in the prompt didn't.
  • The model labels, the code routes: one entry tool classifies task vs. appointment, and routing to SQLite or Google Calendar is deterministic.
  • Safe by construction: messages to third parties only go to saved contacts, so an invented phone number can't be used.
  • Concurrency: a race condition in third-party relays fixed with an atomic claim, validated with parallel requests.
  • Async meeting negotiation as explicit state machines, recurring events as a single RRULE series, and multi-tenant isolation with encrypted OAuth2 refresh tokens.

Running in production

  • GCP VM behind nginx with SSL and Cloudflare DNS; SSH only through IAP, with port 22 closed to the internet
  • Daily SQLite and n8n backups to Cloud Storage with lifecycle rules; restores validated, including during a real incident
  • API token, input validation, rate limits per IP and per client, and a daily cost cap
